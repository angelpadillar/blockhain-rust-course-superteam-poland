## Where the code runs

- VPS `buena-prod-01` (`root@100.121.5.10`), deployment `/opt/buena-multilogin`
  (compose project `buena-multilogin`, launcher + viewer + on-demand worker).
- The new browser code is bind-mounted from `/opt/buena-multilogin-orchestrator`
  (`src/`, `job-runner.mjs`, `profile-health-cli.mjs`, `scripts/`). Sync after a
  change:
  ```sh
  cd agent/multilogin
  tar -czf - job-runner.mjs profile-health-cli.mjs src scripts | \
    ssh root@100.121.5.10 'rm -rf /opt/buena-multilogin-orchestrator/src && tar -xzf - -C /opt/buena-multilogin-orchestrator'
  ```
- Run one job:
  ```sh
  cd /opt/buena-multilogin
  docker compose run --rm --no-deps -T \
    -v /opt/buena-multilogin-orchestrator/src:/app/src:ro \
    -v /opt/buena-multilogin-orchestrator/job-runner.mjs:/app/job-runner.mjs:ro \
    --entrypoint node worker job-runner.mjs /data/jobs/<job>.json \
    --data /data/account-pilot --config config.vps.json --accounts /data/accounts-outlook-linkedin.json \
    --token-file /data/automation-token --provider fireworks --key-file /data/fireworks-api-key \
    --human-checkpoint-seconds 300
  ```
  From the Mac the same thing is `npm run browser:job -- <jobfile> --remote --accounts /data/accounts-outlook-linkedin.json`.

What to expect:
- LinkedIn login → possible "suspicious login" check. The flow clicks LinkedIn's
  own **"Wyślij" (Send code)** button, reads the code from that profile's Hotmail
  inbox (`src/mailbox-code.mjs`, read-only, bounded, never printed), fills it and
  submits. This path is deployed but **not yet proven end-to-end** — watch the
  NDJSON for `"action":"mailbox_code"` (`state:"after"` = code fetched).
- If it escalates to a harder check (`human_verification_required`), the job goes
  to `WAITING_FOR_HUMAN`, preserves the profile and sends a **Discord alert**
  (screenshot + context + resume command). Complete it in the VNC browser:
  `ssh -L 5901:127.0.0.1:5901 root@100.121.5.10` (password in
  `private/vnc-password`), then rerun the same command — the same profile resumes.
- ol-01/ol-02 were each attempted several times, so LinkedIn has escalated them;
  a fresh account is the better test.

## Known gaps / cautions

- LinkedIn escalates after repeated attempts on one profile; do not hammer a
  checkpointed account. Use VNC for the escalated ones.
- The mailbox fill chain needs one clean confirmation run (ol-03).
- Do not reset or recreate the five profiles; their Outlook sessions are proven
  and persisted.
- No CAPTCHA or security control is ever solved automatically; a genuine
  challenge always becomes a human checkpoint.
