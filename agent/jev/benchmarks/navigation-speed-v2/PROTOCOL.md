# Navigation speed candidate v2

Frozen before live requests on 17 September 2026. Machine-readable limits and source identities are in `protocol.json`; the successful baseline's source is preserved under `../navigation-speed-v1/baseline/`.

Run six attempts in this fixed order: baseline, candidate, candidate, baseline, baseline, candidate. This gives three adjacent comparisons, B/C, C/B, B/C. Each starts at the city homepage with a fresh Chromium context using the same persistent account/profile, image, server resource limits, locale and viewport. Both arms share one Jev client process. No warm-up or discarded attempts. Browser/profile and server caches may persist between runs; the order is fixed, not randomized.

The task is unchanged: find the configured merchant and open the exact product. Success requires the store, both product identifiers and visible product title. Account setup is excluded. Repeating the already authorized age confirmation is included. Navigation only; no basket, order, scheduling or purchase action is permitted.

This second cohort follows the retained v1 failure. V1 twice chose unavailable after filling the city search despite an offered submit action. V2 restores the baseline model prompt exactly and retains candidate element binding and readiness. It captures actual nodes with the observation, uses the unchanged baseline model request while retaining element descriptors locally for execution and journaling, and permits at most two pre-dispatch stale refresh/reselections within the existing budgets. It waits 250 ms for a newly observed relevant target, retains the 700 ms fallback and delayed product-title protection, and polls every 75 ms. These results cannot isolate the contribution of each change. Known search text, task restrictions, mutation guards and independent completion remain shared with baseline.

Each attempt allows 20 steps, 120 seconds and $0.02 estimated model cost. Provider/usage, account setup, challenge, cancellation and journal failures stop the batch; ordinary navigation failures remain recorded and the sequence continues. Every attempt is journaled before browser/API work, including failed or interrupted attempts. Unknown usage is never priced as zero.

Primary measures: independently verified completion count; median and range of completed navigation time; all-attempt estimated API cost per verified success. Also report full attempt time, launch time, model calls/latency/tokens, browser/runtime residual and candidate readiness/observation/execution measurements. Observation is included in readiness, so those times must not be summed. Full attempt time includes launch, navigation, close and pending diagnostic writes, but excludes terminal journal and batch writes. Navigation time includes its durable event writes.

Three repetitions per arm on one account/product/region provide descriptive evidence only: no stable p95, general reliability, global speed record, broad merchant coverage or comparison to a larger-model API. Pricing uses configured token rates, with actual returned model versions retained. Infrastructure, setup, operator work and any future planner/writer are excluded. A changed version requires a new named cohort; keep every prior attempt.

Reproduce with `node scripts/navigation-compare-v2.mjs --key-stdin --repeat-confirmed-age` inside the configured isolated service, supplying the key through hidden stdin. Existing account authorization is required. Offline analysis: `python3 analyze_comparison.py PRIVATE_BATCH --journals-dir PRIVATE_RUNS --output results/comparison.json`. Raw browser journals remain private; only allowlisted summaries are published.
