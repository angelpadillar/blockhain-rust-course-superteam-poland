JevTest offers useful verification and replay patterns. It supplies no evidence that its execution is faster or cheaper than our v3 runtime, and it is not an arbitrary-task browser agent. The source is explicitly `UNLICENSED` and private for package publishing. Its licensing document says the intended usage rights have not been adopted and grants no usage or redistribution rights. Incorporate the concepts through our own implementation; do not vendor or transplant its source. [Licensing statement](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/docs/licensing.md#L1-L7), [package metadata](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/package.json).

| Area | What the implementation actually does | Comparison with frozen v3 |
| --- | --- | --- |
| Task architecture | A developer supplies a goal, start URL, fixture values, available actions, readiness callback and executable assertions. A generic runner uses an adapter with observe/execute/check/capture/close methods. | More reusable application integration contracts; v3 is a narrow search-and-open workflow with a real goal-to-task compiler. Neither demonstrates arbitrary instruction following. |
| Observation | Captures URL, up to 8,000 characters of body text, form values, optional application data, current actions, and bounded console/network history. State hash excludes error/network history. | Broader diagnostic context, but larger payloads than v3's selected controls, task and page title. No screenshots are sent to Jev. |
| Available actions | Explicit actions or DOM discovery for click/fill/select/check. Fill/select values must already exist in selector-keyed fixtures. Discovery sorts hashed IDs and truncates at 40. | Select/check are useful primitive additions. Preserve v3's current-node references, semantic validation and target coverage; do not adopt arbitrary truncation or structural-selector identity. |
| Model work | One Choice selects a fully specified action or abort. A second request assesses its observed result as expected/unexpected/uncertain. No helper text LLM, query writer, planner or screenshot reasoning is implemented. | v3 avoids model selection on deterministic steps and pays for semantic ambiguity; its OR planner supplies text. JevTest does not solve the missing-text problem for general tasks. |
| Recovery | Time/step/state-action repetition limits; policy may abort. Execution errors stop the flow. Replay rejects changed state/action/assertions. No automatic API retry, stale-node recovery or planner escalation. | v3 already refreshes stale references before dispatch, with a bounded retry count and no retry of uncertain execution. Keep this behavior. |

There is no operation batching within a flow: select, execute, observe, assert, capture and assess are sequential. Suite concurrency defaults to two independent flows, and the adapter launches a separate Chromium browser for each flow. Selection and assessment of that selected action require different observations; simply placing those questions in one request would remove the post-action evidence. A future controller could ask an assessment of the *previous* action and an independent next-action choice over the same fresh observation, but that is a proposed redesign, not something JevTest implements. The next choice could not depend on the simultaneous assessment's answer. [Execution order](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/runner.ts#L117-L182), [suite concurrency](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/runner.ts#L202-L224), [browser launch](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/browser.ts#L104-L139). Current TypeSafe fan-out documentation was unavailable during this review; the independence rule also appears in the locally installed TypeSafe skill and should be checked against live documentation before a new integration.

The safeguards fit controlled testing. Requests are restricted by origin, with service workers/downloads blocked and popups closed. This does **not** block same-origin POSTs, purchases or destructive actions. Matching one CSS selector proves uniqueness, not that its target is still the same semantic control observed before a model call. Readiness is application supplied, and unconfigured readiness may observe a pending update too early. HTML/screenshot evidence has masking and token redaction, but no general private-data guarantee. Keep v3's request/action guard, screenshot opt-in and semantic freshness checks. [Network policy](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/browser.ts#L126-L175), [execution and capture](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/browser.ts#L216-L275).

The shared concurrent token budget reserves request bytes × 4 plus 4,096 tokens, charges that estimate if usage is unknown, and disables hidden retries. This is admission accounting, not an actual billed-cost measurement or guaranteed spending cap. v3's unknown-cost stop and accounting persisted before model-content interpretation are useful protections to retain. JevTest's complete response schema is parsed before actual usage is added, so some malformed-answer responses can retain an estimate even if usage fields were present. [Budget/provider implementation](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/jev.ts#L31-L161).

The published validation claims 12 flows, six healthy completions, all six planted faults found by both policies, 12 replayed traces, and five faults flagged by the model, using 64 requests and 70,807 input / 2,336 output tokens. Those are author-reported measurements, not independently reproduced here. The named raw artifact directories are not tracked in this checkout, and the pilot did not record the resolved model version. No aggregate comparative latency, speedup or billed dollar figure is supplied. The runner stores a flow duration, which includes setup, model work, evidence and cleanup; that alone is not a published speed comparison. [Validation](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/docs/validation.md#L3-L26), [duration](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/runner.ts#L188-L198).

The benchmark has an additional unblinded input: flow IDs name faults such as `wrong-total`, and `startUrl` contains a `bug=` parameter. Both selection and assessment receive the full flow. The shop's stage-specific action function offers at most one application action plus the policy's abort option. Thus the reported five model candidates do not establish unseen bug-detection ability, and all-six combined detection is largely explained by predefined exact assertions. The documentation itself correctly limits the benchmark to integration/regression validation. [Labelled fixture and actions](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/examples/shop/project.ts#L18-L87), [model input](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/jev.ts#L162-L204), [benchmark caveat](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/docs/validation.md#L26).

Recommended independent incorporations, in priority order:

1. **A reusable task contract with invariants and explicit completion assertions.** Let workflow adapters supply task-specific readiness and observed invariants while keeping expected answers outside policy input. Exact checks decide completion; a semantic assessment is a separately labelled candidate signal only when useful. v3 already has an external verifier; the new work is making this contract reusable beyond search-and-open. Avoid paying for a post-action assessment when deterministic evidence already resolves it. [JevTest check logic](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/runner.ts#L21-L32).
2. **Validated workflow memory with fresh bindings and progress checks.** Store a successful public task/primitive trace, its relevant preconditions and outcome checks. On reuse, observe again and bind each operation to a fresh v3 node reference; run it only while preconditions still match. Drift returns control to bounded Jev selection or planner fallback. Keep a state/action repetition counter to prevent loops. JevTest's replay checks and observed graph are useful precedents, but its replay is currently an offline reproducibility tool, not an adaptive workflow cache. [Replay](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/replay.ts#L43-L89), [observed graph](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/graph.ts#L11-L30), [repetition bound](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/runner.ts#L128-L134).
3. **General typed primitive candidates with bound arguments.** Expand the browser adapter to observed buttons, selects, checkboxes and appropriate keyboard primitives. Build valid operation/target/value combinations in code; use one bounded Jev Choice when intent is ambiguous. Source values from the user, deterministic extraction or a budgeted writer fallback. Preserve an abstain option, permission checks, freshness validation and candidate coverage. JevTest demonstrates prebound fill/select/check actions; it does not supply the text-generation fallback or general planner. [Action contract](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/types.ts#L3-L10), [fixture-bound actions](https://github.com/CorieW/JevTest/blob/cb5326eb2419e9a7612f8de5a596039e10b1916b/src/browser.ts#L77-L95).

A useful next experiment is a separate candidate, with frozen v3 retained. Use held-out branching local fixtures with renamed products/regions, randomized answer routes and no fault labels in model input. Compare deterministic workflow reuse, Jev only for ambiguous decisions, and a budgeted writer/planner fallback. Report complete and failed attempts, actual semantic/model activations, stale recovery, end-to-end time and all known/unknown costs. Then evaluate a small predeclared set of public read-only sites separately, so merchant outages do not masquerade as executor performance and known answer URLs never enter the policy.
