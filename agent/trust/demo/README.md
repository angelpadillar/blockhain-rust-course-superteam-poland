# Buena local gift approval demo

```sh
node trust-layer/demo/server.mjs
```

Open the printed loopback URL (default `http://127.0.0.1:4317`). Set `TRUST_DEMO_PORT` to use a different port. Node 22+ is sufficient; there are no external dependencies. Stop the process with Ctrl-C.

This is a **local simulation**. It has no wallet, private key, payment provider, real merchant, delivery system or blockchain connection. The page says so explicitly. It demonstrates a quote/approval boundary; a local button click is not an authenticated sender signature. All names, items and recipients are fictional.

The five scenarios cover matching details, a price increase after approval, a changed merchant, an expired quote, and replay of a used approval. Review and approve the displayed exact quote hash, then ask the server to simulate the final check. For replay, complete the first simulated execution and click “Test a repeat attempt.” Expiry uses an explicitly advanced demo clock. Rejecting an attempt never creates a payment or a second execution.

The server enforces merchant, product, quantity, currency, budget, expiry, quote hash and one-use authorization. A quote change cannot inherit approval. It serializes requests per browser session, checks same-origin mutations, and saves atomic JSON receipts under `receipts/` before responding. Restarting loses browser sessions but retains their local receipt files; this is not a durable production authorization service. The filenames and session IDs are generated by the server. Browser clients cannot upload a new state, choose a receipt path or load a key.

`../evidence.mjs` supplies append-only hash-linked records and independent correlation checks. The UI distinguishes an intact record chain from missing screenshot evidence. It never treats an unattached screenshot as verified. Hashes alone do not authenticate the person, prove real merchant facts, or detect a complete rewrite without a separately trusted head.

Run local checks:

```sh
node --test trust-layer/demo/demo.test.mjs
```

To preserve **real local browser screenshots**, the test harness captures quote, approved and confirmed pages, writes a public structured observation for each, and supplies an offline manifest:

```json
[
  {
    "stage": "quote",
    "eventHash": "exact hash of the corresponding quote envelope",
    "screenshotPath": "quote.png",
    "observationPath": "quote-observation.json"
  }
]
```

Include every reached boundary (`quote`, `approval`, `confirmation`) and use the exact stage's earlier envelope hash. An observation uses the evidence library's allowlisted schema: `kind`, `observedAt`, optional public title/headings/items/merchant/currency/total and correlation IDs. It must describe what the capture actually shows. Paths are relative to the manifest. Then run:

```sh
node trust-layer/demo/attach-evidence.mjs receipt.json captures.json new-sealed-receipt.json
```

This offline tool checks PNG containers, hashes the supplied bytes/observations, appends boundary-evidence records and requires complete strict verification before writing a **new** output file. It does not generate screenshots or infer their contents. Screenshot and observation files remain adjacent artifacts; their hashes and relative paths appear in the sealed receipt. Anchor the printed final head separately when protection against history replacement is needed. The running UI's chain is intentionally not rewritten by this offline step.

The Rust work and this local evidence format share exact-terms, expiry and one-use semantics. This JSON quote hash is **not** claimed to be the Rust program's domain-separated transaction digest or a deployed instruction. The existing project currently uses an Anchor CLI and terminal sender approval; connecting a frontend wallet and authenticated signing remains separate work.
